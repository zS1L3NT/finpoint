# Domain docs

This repo uses a single-context domain layout.

## Before exploration

- Read `CONTEXT.md` for canonical terms and avoided aliases.
- Read relevant decisions under `docs/adr/`, when present.
- Read `GLOSSARY.md`, when present, as supplementary documentation.
  Surface any conflict with `CONTEXT.md` rather than silently overriding it.

Missing optional documents do not block work.

## Writing

Use the canonical vocabulary in specs, tickets, code, and tests.
Surface conflicts with existing ADRs before changing the documented behavior.
